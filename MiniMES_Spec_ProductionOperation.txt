2. DECISÕES DE PROJETO
----------------------

2.1 Agregado
    ProductionOrder é raiz de agregado; Operations é coleção filha da ordem.
    Motivo: as três invariantes do spec §16.3 precisam enxergar os irmãos
    ("sequência única por ordem", "operação anterior deve estar concluída antes
    da próxima iniciar", "só conclui a ordem quando todas as operações estiverem
    concluídas"). Dentro da entidade elas são um `if`; com entidade solta viram
    query extra no service e a invariante vaza do domínio.

    Consequência: NÃO existe IProductionOperationRepository nem
    IProductionOperationService. A operação não tem caminho de escrita próprio.
    Program.cs não muda.

    Observação: isso difere do estilo usado em ProductionOrder -> Product, que é
    FK sem navigation property. Ali é referência; aqui é composição.

2.2 Status
    Apenas os status que o Production consegue dirigir:
    Pending, InProgress, Completed, Cancelled.
    Ready(2) e Paused(4) do spec ficam de fora — nada no Production os dispara
    (são conceitos do futuro Execution service). A numeração do spec é
    preservada (2 e 4 ficam vagos) e o status é persistido como string, então
    acrescentá-los depois não exige migration de dados.

2.3 HTTP
    Além do POST .../operations exigido pelo MVP, expor start/complete/cancel da
    operação como endpoints provisórios, aninhados na ordem. Mesmo status
    "provisório: virá do Execution" que já vale para start/complete da ordem.
    Sem eles, a regra "só conclui a ordem com todas as operações concluídas" não
    é exercitável pela API.

2.4 WorkCenterId
    Guid obrigatório, coluna work_center_id uuid NOT NULL, SEM foreign key.
    WorkCenter pertence ao serviço Catalog, que não existe — não há tabela para
    apontar. Referência solta, conforme a regra do README: "referências entre
    serviços são Guid solto, validadas por API/evento". Validação entra quando o
    Catalog existir.

2.5 Version
    ProductionOperation NÃO tem token de concorrência. O spec §16.3 não lista
    Version para ela, e a concorrência já é guardada pelo Version da ordem, que
    é rotacionado a cada mutação de operação (add/start/complete/cancel).
    Duas requisições concorrentes sobre operações da mesma ordem colidem no
    UPDATE de production_orders e resultam em 409.

    private ProductionOperation() { }

    public ProductionOperation(
        Guid productionOrderId,
        int sequence,
        string code,
        string description,
        Guid workCenterId,
        decimal plannedQuantity,
        int? targetCycleTimeSeconds = null
    )

    Validações no ctor (todas -> DomainException, mensagem em inglês):
      - sequence <= 0            "Sequence must be greater than zero."
      - code em branco           "Operation code is required."
      - description em branco    "Operation description is required."
      - plannedQuantity <= 0     "Planned quantity must be greater than zero."
      - targetCycleTimeSeconds informado e <= 0
                                 "Target cycle time must be greater than zero."

    Atribuições:
      Id = Guid.NewGuid();
      Status = ProductionOperationStatus.Pending;
      (demais campos vindos dos parâmetros)

    Nota: o ctor é público, mas o único chamador legítimo é
    ProductionOrder.AddOperation. Não é `internal` porque o projeto de testes é
    outro assembly.

4.3 Métodos de transição

    Cada método guarda apenas o próprio status. A regra de precedência entre
    operações mora em ProductionOrder, que é quem enxerga os irmãos.

    public void Start()
        Só de Pending.
        Erro: $"Only a pending operation can be started. Current status: {Status}."
        -> InProgress

    public void Complete()
        Só de InProgress.
        Erro: $"Only an in-progress operation can be completed. Current status: {Status}."
        -> Completed

    public void Cancel()
        De qualquer status exceto Completed.
        Erro: "A completed operation cannot be cancelled."
        -> Cancelled

4.4 Tabela de transições

    Pending     -> InProgress   (Start)
    Pending     -> Cancelled    (Cancel)
    InProgress  -> Completed    (Complete)
    InProgress  -> Cancelled    (Cancel)
    Completed   -> (terminal)
    Cancelled   -> (terminal)

5.3 AddOperation

    public ProductionOperation AddOperation(
        int sequence,
        string code,
        string description,
        Guid workCenterId,
        decimal plannedQuantity,
        int? targetCycleTimeSeconds = null
    )

    Regras, em ordem:
      1. Status deve ser Draft.
         // ponytail: só Draft aceita operações; abrir para Released quando
         // houver caso de uso real.
         Erro: $"Operations can only be added to a draft order. Current status: {Status}."
      2. Sequence não pode já existir na ordem (spec §16.3: "sequência única por
         ordem").
         Erro: $"Sequence {sequence} is already used in order {OrderNumber}."
      3. Instancia ProductionOperation(Id, sequence, ...), adiciona a _operations.
      4. Version = Guid.NewGuid();
      5. Retorna a operação criada.

    A validação de sequência duplicada existe em dois níveis: aqui (mensagem de
    negócio, 422) e no índice único do banco (§6.1, rede de segurança contra
    corrida — resulta em 500/DbUpdateException; não é o caminho esperado).

5.4 StartOperation

    public void StartOperation(Guid operationId)

    Regras, em ordem:
      1. Status da ORDEM deve ser InProgress.
         Erro: $"Operations can only be started on an in-progress order. Current status: {Status}."
      2. Localiza a operação (§5.2).
      3. Precedência (spec §16.3: "operação anterior deve estar concluída antes
         da próxima iniciar"): toda operação com Sequence MENOR que a alvo deve
         estar Completed ou Cancelled.

         bool previousPending = _operations.Any(other =>
             other.Sequence < operation.Sequence
             && other.Status != ProductionOperationStatus.Completed
             && other.Status != ProductionOperationStatus.Cancelled
         );

         Erro: $"Operation {operation.Sequence} cannot start while a previous operation is not completed."
      4. operation.Start();
      5. Version = Guid.NewGuid();

5.5 CompleteOperation / CancelOperation

    public void CompleteOperation(Guid operationId)
    public void CancelOperation(Guid operationId)

    Localizam a operação (§5.2), delegam para operation.Complete() /
    operation.Cancel(), e rotacionam Version. Sem guarda adicional no nível da
    ordem — completar/cancelar uma operação não depende dos irmãos.

5.6 Release() — substituir o marcador da linha 73

    if (_operations.Count == 0)
    {
        throw new DomainException(
            "A production order requires at least one operation before release."
        );
    }

    A guarda vem DEPOIS da checagem de Status != Draft (mantém a ordem de
    mensagens: primeiro o estado, depois o conteúdo).

5.7 Complete() — substituir o marcador da linha 101

    // ponytail: operação cancelada não bloqueia a conclusão — leitura literal do
    // spec ("todas concluídas") travaria a ordem para sempre.
    bool pendingOperations = _operations.Any(operation =>
        operation.Status != ProductionOperationStatus.Completed
        && operation.Status != ProductionOperationStatus.Cancelled

    if (pendingOperations)
    {
        throw new DomainException(
            "All operations must be completed or cancelled before completing the order."

    }
